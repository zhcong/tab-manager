# 独立窗口模式实时更新 — 设计文档

日期：2026-05-06

## 目标

在独立窗口模式（`popup.html?windowMode=true`）下实现实时更新，当标签页/窗口发生变化时，列表自动刷新，无需手动操作。

## 范围

实时反映以下全部变化：
- 新标签页打开 → 列表中新增
- 标签页关闭 → 列表中被删除
- 窗口关闭 → 对应组标记为"已关闭"
- 标签页 URL/标题/favicon 更新 → 列表中同步更新

## 方案

通过 `chrome.storage.onChanged` 事件监听 storage 变更，不修改 `background.js`。

### 数据流

```
background.js 写入 storage
       ↓
chrome.storage.onChanged 事件（Chrome 内置跨页面广播）
       ↓
popup.js（窗口模式）收到通知 → 重新加载数据 → 智能合并渲染
```

### 改动范围

仅 `popup.js`，约 40 行新增代码。`background.js` 完全不动。

## 实现要点

### 1. 条件启用

仅在 `?windowMode=true` 时注册监听器，普通 popup 不受影响。

### 2. 300ms 防抖

连续 storage 写入（如批量关闭标签页）合并为一次刷新，避免频繁渲染。

### 3. 状态保持（smartRender）

re-render 前后保留用户操作状态：
- 搜索框文本不丢失
- 每个组的展开/折叠状态还原
- 若检测到正在编辑组名（`.label-input` 存在），跳过本次刷新，编辑失焦后再补刷新

### 4. 监听器生命周期

`chrome.storage.onChanged` 监听器在页面销毁时由 Chrome 自动清理，无需手动注销。

## 边界处理

| 场景 | 处理方式 |
|------|---------|
| 连续批量变更 | 300ms 防抖合并为一次 |
| 用户正在编辑组名 | 跳过刷新，编辑完成后再补刷 |
| 用户正在搜索 | 保持搜索文本，重新执行过滤渲染 |
| 用户折叠了某些组 | 恢复折叠状态 |
| 用户操作触发了自身刷新（如点击删除） | 防抖确保不重复渲染 |

## 不在范围内

- 不修改 `background.js`
- 不为普通 popup 模式添加实时更新（普通 popup 每次打开都会重新加载）
